# Render deploy

Blueprint: `deploy/render.yaml`. Live URL: https://micro-git.onrender.com (health: `GET /health`).

## Create the services from the Blueprint

1. Render dashboard > New > Blueprint.
2. Connect the GitHub repository `L0nelyG0d/micro-git`.
3. Set the Blueprint path to `deploy/render.yaml`.
4. Review the resources and click Apply. Render builds and starts everything.

## What the Blueprint creates

- A web service `mg`, `runtime: docker`, built from the root `Dockerfile` (`dockerContext: .`), plan `free`, health check `/health`, `autoDeploy: true`.
- A managed Postgres database `mg-db` (database `mg`, user `mg`, plan `free`).
- Environment: `STORE=db`, `DB_DRIVER=postgres`, `DATABASE_URL` taken from the `mg-db` connection string, `JWT_SECRET` generated by Render, `COOKIE_SECURE=true`.

## Docker Compose is not used

Render builds the Dockerfile; it does not run `docker-compose.yml`. A Compose-only deployment goal is met in spirit by the same root Dockerfile plus a Postgres database, which is what the Blueprint provisions.

## Hook for CD

1. Service > Settings > Deploy Hook: copy the hook URL (treat it as a secret).
2. In GitHub: Settings > Secrets and variables > Actions > New repository secret, name `RENDER_DEPLOY_HOOK`, paste the URL.
3. After CI and E2E pass on `main`, `.github/workflows/deploy.yml` POSTs to it. See `deploy/README.md`.

`autoDeploy: true` also deploys on every push by itself, possibly before CI is green; see `deploy/README.md` for turning it off.

## Free-tier limits

Stated in `deploy/render.yaml`: the free web service sleeps when idle (the first request after a sleep is slow), and the free Postgres expires after 30 days. Check Render's current pricing page for other limits; I did not verify them.

## Service name: mg vs micro-git

The Blueprint names the web service `mg`. `deploy/render/LIVE.md` names the live service `micro-git` (URL https://micro-git.onrender.com). I cannot tell from the repository whether the live service was created from this Blueprint or by hand, so which name Render actually shows is unverified. Check the Render dashboard. The `RENDER_DEPLOY_HOOK` must belong to the live service. (A GET to `/health` on the live URL returned HTTP 200 when this was written.)
