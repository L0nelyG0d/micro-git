# Render deploy

Blueprint: `deploy/render.yaml`. Live URL: https://micro-git.onrender.com (health: `GET /health`).

## Create the services from the Blueprint (new Render account only)

Use these steps only on an account that has no `micro-git` service yet. The live service already exists: never create a new Blueprint against it (Render would create a second, suffixed set of resources). For the live service, and for the full procedure, see `_docs/deploy-render.md`.

1. Render dashboard > New > Blueprint.
2. Connect the GitHub repository `L0nelyG0d/micro-git`.
3. Set the Blueprint path to `deploy/render.yaml`.
4. Review the resources and click Apply. Render builds and starts everything.

## What the Blueprint creates

- A web service `micro-git`, `runtime: docker`, built from the root `Dockerfile` (`dockerContext: .`), plan `free`, health check `/health`, `autoDeploy: false` (the CI/E2E-gated deploy hook is the only trigger).
- A managed Postgres database `mg-db` (database `mg`, user `mg`, plan `free`).
- Environment: `STORE=db`, `DB_DRIVER=postgres`, `DATABASE_URL` taken from the `mg-db` connection string, `APPLY_SCHEMA=true` (applies the embedded schema at startup), `JWT_SECRET` generated by Render, `COOKIE_SECURE=true`.

## Docker Compose is not used

Render builds the Dockerfile; it does not run `docker-compose.yml`. A Compose-only deployment goal is met in spirit by the same root Dockerfile plus a Postgres database, which is what the Blueprint provisions.

## Hook for CD

1. Service > Settings > Deploy Hook: copy the hook URL (treat it as a secret).
2. In GitHub: Settings > Secrets and variables > Actions > New repository secret, name `RENDER_DEPLOY_HOOK`, paste the URL.
3. After CI and E2E pass on `main`, `.github/workflows/deploy.yml` POSTs to it. See `deploy/README.md`.

If the live service is not managed by this Blueprint, `autoDeploy` may still be on in the dashboard and deploys on every push, possibly before CI is green; see `deploy/README.md` for turning it off.

## Free-tier limits

Stated in `deploy/render.yaml`: the free web service sleeps when idle (the first request after a sleep is slow), and the free Postgres expires after 30 days. Check Render's current pricing page for other limits; I did not verify them.

## Service name

The Blueprint service is named `micro-git`, matching the live service (https://micro-git.onrender.com). Do not create a new Blueprint against the live service; see `_docs/deploy-render.md` for how to adopt it safely, the `APPLY_SCHEMA` behavior and the post-deploy smoke job. The `RENDER_DEPLOY_HOOK` must belong to the live service.
